2. VISÃO GERAL DO PROJETO (HSP VEHICLE INTELLIGENCE)
================================================================================
O HSP Vehicle Intelligence é uma plataforma modular de coleta, normalização e inteligência de dados automotivos. O sistema varre portais de venda de veículos, extrai informações estruturadas de anúncios, monitora o histórico de preços e armazena os dados em um repositório central para alimentar um precificador inteligente.

2.1 Módulos Centrais do Ecossistema
1. HSP Collector Builder (Gerador de Coletores): O motor central encarregado de criar scripts de captura sob demanda. Ele analiza o comportamento de um site alvo (como paginação, estrutura do HTML e campos de dados) e gera de forma autônoma um script coletor específico para aquele portal.
2. HSP Veículos (Core / API): A camada de inteligência e persistência de dados. Desenvolvida em FastAPI (Python) e integrada a uma interface gráfica em Flet, ela gerencia o banco de dados relacional Neon (PostgreSQL), processa o catálogo mestre de veículos e calcula variações de preço ao longo do tempo.

3.2 Dicionário de Componentes (O que é cada pasta?)
* interface/: Guarda a camada visual ou de interação do usuário com o construtor de coletores. O arquivo app.py é o ponto de partida que inicializa a aplicação.
* engine/: O coração algorítmico do sistema. Contém os motores de descoberta de URLs (discovery.py), gerenciamento de requisições de rede (network.py), análise de código HTML (html_analyzer.py), identificação de padrões de paginação (pagination.py), detecção de blocos de veículos (vehicle_detector.py), extração de campos específicos (field_detector.py), validação de dados (validator.py) e o gerador final do script autônomo (generator.py).
* schemas/: Define os contratos de dados e validações estruturais. O arquivo meta_vehicle.py dita a regra de quais campos um carro precisa ter para ser aceito pelo sistema.
* collectors/generated/: O repositório de destino onde os novos scripts de raspagem gerados pela engine serão salvos e executados de forma isolada.
* investigations/: Espaço dedicado ao armazenamento de relatórios, análises de tráfego de rede, amostras de HTML bruto e logs de engenharia reversa de sites complexos.
* tests/: Armazena os scripts de testes automatizados para garantir que nenhuma alteração na engine quebre coletores existentes.

Esta seção documenta os comandos exatos utilizados para preparar o ambiente de desenvolvimento, criar a estrutura física de arquivos e resolver problemas de caminhos no terminal.

4.1 Criação da Estrutura Física de Pastas e Arquivos
Para criar toda a árvore de diretórios do HSP Collector Builder de uma só vez, utilize o comando correspondente ao terminal do seu ambiente operacional.

Procedimento para Ambientes Windows (PowerShell)
1. Abra o terminal PowerShell diretamente na pasta raiz do seu projeto no VS Code.
2. Copie, cole e execute o comando exato abaixo em uma única linha:
New-Item -ItemType Directory -Path "interface", "engine", "schemas", "collectors/generated", "investigations", "tests"; New-Item -ItemType File -Path "interface/app.py", "engine/discovery.py", "engine/network.py", "engine/html_analyzer.py", "engine/pagination.py", "engine/vehicle_detector.py", "engine/field_detector.py", "engine/validator.py", "engine/generator.py", "schemas/meta_vehicle.py"

Procedimento para Ambientes Linux / macOS (Bash)
1. Abra o terminal do sistema operacional na raiz do projeto.
2. Execute o comando composto abaixo:
mkdir -p interface engine schemas collectors/generated investigations tests && touch interface/app.py engine/{discovery,network,html_analyzer,pagination,vehicle_detector,field_detector,validator,generator}.py schemas/meta_vehicle.py

4.2 Ativação e Execução de Scripts no Ambiente Virtual (Windows)
A execução de scripts Python em ambiente de desenvolvimento deve ocorrer de maneira estrita dentro do ambiente virtual (.venv) para evitar conflitos de dependências globais.

Execução via Atalho Direto do Executável (Recomendado para evitar falhas de escopo)
.\.venv\Scripts\python.exe saida/dados_olx/olx_gerador.py

Execução via Comando Simplificado (Necessita ativação prévia)
python saida/dados_olx/olx_gerador.py

5.1 PORTAL 1: D MOTORS
5.1.1 Diagnóstico Técnico e Comportamento da Plataforma
O site D Motors expõe seus dados de anúncios de veículos através de uma estrutura de renderização que permite a extração direta via requisições HTTP.

5.1.2 Camada 1: Explicação do Funcionamento do Script
1. Configuração de Destino: Define a pasta para salvar os resultados (saida/dados_dmotors/).
2. Conexão com o Site: O script faz uma requisição HTTP fingindo ser um navegador comum através de um cabeçalho padrão (User-Agent).
3. Varredura e Captura: Ele lê o código da página e busca pelos blocos de texto estruturados que representam os anúncios dos carros.
4. Exportação Segura: Escreve em formato CSV.

5.1.3 Camada 2: Código Fonte Completo (D Motors Coletor)
import csv
import json
import os
from pathlib import Path
import re
import bs4
from bs4 import BeautifulSoup
import requests

PASTA_SAIDA = Path(__file__).resolve().parent
ARQUIVO_CSV = PASTA_SAIDA / "dados_dmotors.csv"
PASTA_SAIDA.mkdir(parents=True, exist_ok=True)

URL_ALVO = "https://www.dmotors.com.br/veiculos"
HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
}

try:
    resposta = requests.get(URL_ALVO, headers=HEADERS, timeout=15)
    if resposta.status_code == 200:
        soup = BeautifulSoup(resposta.content, "html.parser")
        cards_veiculos = soup.find_all("div", class_="card-veiculo") or soup.find_all("div", class_="item-vitrine")
        veiculos_processados = []
        for card in cards_veiculos:
            try:
                titulo = card.find("h2").text.strip() if card.find("h2") else "N/A"
                preco = card.find("span", class_="preco").text.strip() if card.find("span", class_="preco") else "N/A"
                detalhes = card.find("div", class_="detalhes").text.strip() if card.find("div", class_="detalhes") else ""
                veiculos_processados.append({"titulo": titulo, "preco": preco, "detalhes": detalhes})
            except Exception:
                pass
        with open(ARQUIVO_CSV, mode="w", encoding="utf-8", newline="") as f:
            escritor = csv.DictWriter(f, fieldnames=["titulo", "preco", "detalhes"])
            escritor.writeheader()
            escritor.writerows(veiculos_processados)
except Exception:
    pass

5.2 PORTAL 2: QUITCAR
5.2.3 Camada 2: Código Fonte Completo (Quitcar Coletor)
import csv
from pathlib import Path
from bs4 import BeautifulSoup
import requests

PASTA_SAIDA = Path(__file__).resolve().parent
ARQUIVO_CSV = PASTA_SAIDA / "dados_quitcar.csv"
PASTA_SAIDA.mkdir(parents=True, exist_ok=True)

BASE_URL = "https://www.quitcar.com.br/estoque?page="
HEADERS = {"User-Agent": "Mozilla/5.0"}
veiculos_totais = []
pagina_atual = 1

while True:
    url = f"{BASE_URL}{pagina_atual}"
    try:
        resposta = requests.get(url, headers=HEADERS, timeout=15)
        if resposta.status_code != 200: break
        soup = BeautifulSoup(resposta.content, "html.parser")
        anuncios = soup.find_all("div", class_="announcement-item")
        if not anuncios: break
        for anuncio in anuncios:
            nome = anuncio.find("h3").text.strip() if anuncio.find("h3") else "N/A"
            preco = anuncio.find("div", class_="price").text.strip() if anuncio.find("div", class_="price") else "N/A"
            veiculos_totais.append({"nome": nome, "preco": preco, "ano_km": "N/A"})
        pagina_atual += 1
    except Exception: break

if veiculos_totais:
    with open(ARQUIVO_CSV, mode="w", encoding="utf-8", newline="") as f:
        escritor = csv.DictWriter(f, fieldnames=["nome", "preco", "ano_km"])
        escritor.writeheader()
        escritor.writerows(veiculos_totais)
