--------------------------------------------------------------------------------
Disciplina 1.1 — Fundamentos de IA, ML e LLMs
Carga: 40h | Pré-requisito: Nenhum
--------------------------------------------------------------------------------

📚 EMENTA
- História da IA: da "máquina inteligente" aos LLMs
- Linha do tempo: ML → DL → LLMs → Ferramentas atuais
- Arquitetura Transformer: embeddings, atenção, camadas
- Diferença entre ML, DL, IA e LLMs
- Tensores, redes neurais e como aprendem
- Ciclo completo: dados → treino → validação → inferência

🎯 OBJETIVOS DE APRENDIZAGEM
Ao final, o aluno será capaz de:
1. Explicar a evolução histórica da IA até os LLMs
2. Descrever o funcionamento interno de um Transformer
3. Diferenciar ML, DL e IA com exemplos práticos
4. Operar múltiplos modelos locais via Ollama
5. Comparar respostas de diferentes modelos

🧪 PRÁTICA ADAPTADA
- Orquestração de modelos locais com Ollama (RTX 3060)
- Comparação: Llama 3, Mistral, Qwen, Phi
- Benchmark de latência, qualidade e uso de VRAM
- Entrega: CLI Python que consulta múltiplos modelos e compara respostas

❓ PERGUNTAS SOCRÁTICAS
- "Por que a atenção é mais eficiente que RNNs para sequências longas?"
- "O que muda no tensor quando passamos de 7B para 70B parâmetros?"
- "Como você mediria a 'qualidade' de uma resposta sem um humano?"

📖 BIBLIOGRAFIA
- Vaswani et al. (2017) — Attention Is All You Need
- Jay Alammar — The Illustrated Transformer
- Documentação Ollama + Hugging Face

Disciplina 1.2 — Engenharia de Prompts Avançada
Carga: 40h | Pré-requisito: 1.1
--------------------------------------------------------------------------------

📚 EMENTA
- Prompt chaining (encadear prompts para tarefas complexas)
- Prompt templates para padronizar fluxos
- Few-shot, Zero-shot, Chain-of-Thought (CoT)
- Estratégias para reduzir alucinações
- Padrões de prompt para: codar, debugar, documentar, aprender
- Otimização de tokens e custo-eficiência

🎯 OBJETIVOS DE APRENDIZAGEM
1. Escrever prompts que geram respostas consistentes
2. Aplicar chaining em tarefas multi-etapas
3. Criar biblioteca de templates reutilizáveis
4. Medir e reduzir alucinações
5. Otimizar consumo de tokens

🧪 PRÁTICA
- Construir Prompt Library em Python (versionada)
- Testes A/B entre variantes de prompt
- Entrega: Sistema de templates com versionamento e testes automatizados

❓ PERGUNTAS SOCRÁTICAS
- "Como você estruturaria um prompt para que o modelo 'pense em voz alta'?"
- "Qual o trade-off entre few-shot e fine-tuning?"
- "Como detectar que uma resposta é alucinação?"

Disciplina 2.1 — RAG e Busca Semântica
Carga: 40h | Pré-requisito: 1.3

📚 EMENTA

🎯 OBJETIVOS DE APRENDIZAGEM

5. Avaliar qualidade de recuperação

🧪 PRÁTICA ADAPTADA
- pgvector + SQLAlchemy + FastAPI (em vez de Postgres com JS)
- Pipeline robusto de indexação e consulta
- Documentos do mercado automotivo
- Entrega: RAG funcional para documentos automotivos

- "Como você decidiria o tamanho ideal de chunk?"

Disciplina 3.1 — Agentes Autônomos: Fundamentos
Carga: 40h | Pré-requisito: 2.3
--------------------------------------------------------------------------------

📚 EMENTA
- Agent loop: percepção → raciocínio → ação → feedback
- Estrutura interna: planner, executor, memory store, toolbox
- Tipos: task-based, interactive, goal-oriented, autonomous
- Padrões de raciocínio: ReAct, Plan-and-Execute, Reflection
- Function calling e tool use
- Design de schemas JSON para funções executáveis
- Conexão com APIs REST, bancos, automações, MCPs
- Memória: curta, longa, episódica, contextual
- Reflection loops e autoavaliação
- Guardrails e human-in-the-loop
- Prevenção de runaway loops e abusos de API

🎯 OBJETIVOS DE APRENDIZAGEM
1. Implementar agent loop completo
2. Aplicar ReAct e Plan-and-Execute
3. Criar schemas JSON para tools
4. Implementar sistemas de memória
5. Adicionar guardrails e HITL

🧪 PRÁTICA

- Entrega: Agente ReAct funcional com logs e feedback loops

❓ PERGUNTAS SOCRÁTICAS
- "Como você evita que um agente entre em loop infinito?"
- "Quando usar ReAct vs Plan-and-Execute?"
- "Como estruturar memória de longo prazo sem estourar contexto?"

Disciplina 4.1 — AI-Driven DevOps, FinOps e Observabilidade
Carga: 40h | Pré-requisito: 3.3

📚 EMENTA

FUNDAMENTOS DE IA GENERATIVA PARA INFRAESTRUTURA
- Arquitetura de LLMs para infra
- APIs: OpenAI, Anthropic, AWS Bedrock
- Frameworks: LangChain, CrewAI, AutoGen
- RAG aplicado a documentação técnica

IAC ASSISTIDO POR IA
- Tradução NL → Infrastructure as Code
- Geração de Terraform, Pulumi, Helm Charts
- Validação: terraform plan, validate
- Policy-as-Code: OPA, Sentinel
- Detecção de drift

AGENTES PARA KUBERNETES
- Geração de YAML via NL
- HPA/VPA inteligentes
- Autoscaling baseado em workload
- Rollout/rollback guiados por IA (canary, blue-green)
- GitOps: Argo CD, Flux

TROUBLESHOOTING ASSISTIDO
- ReAct para diagnóstico estruturado
- CrashLoopBackOff, ImagePullBackOff, OOMKilled
- Análise de logs distribuídos e traces
- Correlação Jaeger/Zipkin

AIOPS E OBSERVABILIDADE
- PromQL e LogQL a partir de NL
- Dashboards Grafana contextualizados
- Detecção de anomalias (Prophet, Isolation Forest)
- Alertas preditivos

CHATOPS
- Bots para Slack, Discord, Teams
- Comandos: /deploy, /scale, /rollback, /investigar
- Workflows de aprovação com guardrails
- RBAC e auditoria

SEGURANÇA E COMPLIANCE
- Scan IaC e containers (Snyk, Trivy, Checkov)
- AI fix automático de vulnerabilidades
- Detecção de secrets
- Relatórios SOC2, ISO 27001, PCI-DSS

CI/CD COPILOT
- Pipelines GitLab CI, GitHub Actions, Jenkins
- Gates inteligentes: SAST, DAST, dependency scanning
- Análise de impacto em PRs
- Rollback automático

FINOPS
- Estimativa de custos em PRs (Infracost)
- Rightsizing de pods e nodes
- Instâncias spot e reservadas
- Detecção de zombie resources
- Forecasting de custos

RAG DE RUNBOOKS
- Indexação de playbooks, READMEs, wikis
- Agente que consulta e executa runbooks
- Post-mortem blameless automatizado

AUTO-REMEDIAÇÃO SEGURA
- Playbooks acionados por alertas
- Fluxo: alerta → verificação → mitigação → validação
- Canary automático com rollback
- Circuit breakers
- Dry-run antes de produção
- HITL para ações críticas

Disciplina 4.3 — Fine-Tuning e Processamento de Dados
Carga: 40h | Pré-requisito: 4.2
--------------------------------------------------------------------------------

📚 EMENTA

QUANDO FAZER FINE-TUNING (DECISION FRAMEWORK)
- RAG vs fine-tuning vs prompt engineering

PREPARAÇÃO DE DATASETS
- Coleta de dados relevantes
- Limpeza, balanceamento, padronização
- Formato JSONL
- Automação com Python

FINE-TUNING VIA OPENAI API
- Upload e train
- Hiperparâmetros
- Monitoramento
- Versionamento e documentação

LORA E PEFT
- Low-Rank Adaptation
- Parameter-Efficient Fine-Tuning
- Trade-offs: desempenho vs eficiência
- Full fine-tuned vs LoRA

AVALIAÇÃO DE MODELOS
- Métricas qualitativas e quantitativas
- Precisão, consistência, adequação
- Testes A/B
- Overfitting e generalização

PROJETO FINAL
- Modelo customizado para domínio específico (atendimento, suporte, jurídico, financeiro)

🎯 OBJETIVOS DE APRENDIZAGEM
1. Decidir quando fazer fine-tuning
2. Preparar datasets em JSONL
3. Executar fine-tuning via API
4. Aplicar LoRA/PEFT
5. Avaliar modelos fine-tunados

🧪 PRÁTICA
- Fine-tuning de modelo para domínio automotivo
- Entrega: Modelo customizado integrado a chatbot
